# V.90 and V.92 implementation status

Updated 2026-10-10. Protocol authority: [ITU-T V.92](https://www.itu.int/rec/T-REC-V.92/en).

## Current service

The answerer implements V.90 downstream PCM with V.34 upstream. Real modem tests have reached CONNECT, negotiated PPP and downloaded web pages. A CONNECT indication alone does not establish usable traffic or long-term reliability.

A transparent G.711 path can preserve chosen PCM levels through the 8 kHz linear AudioSocket interface. Transcoding, gain changes, packet loss, clock drift and audio processing can prevent training or interrupt data transfer.

## Experimental Quick Connect

Set `V92_QUICK_CONNECT=1` to enable the experimental digital Quick Connect controller and V.92 capability negotiation. The controller handles repeated QC1a requests, QCA1d, QTS, ANSpcm, TONEq and handover. Phase 2 supports the caller's shortened QAM profile, including its carrier selection, and falls back to full Phase 2 when the required response is absent. LAPM detection is bypassed when the negotiated V.92 path declares LAPM.

A caller can request zero DIL on a shortened call. The answerer measures broadband echo from known TRN1d after the peer's transmit tail has cleared, then stops collecting before Jd. This avoids leaving the earlier narrowband echo estimate in place during final training.

Local Conexant hardware tests have completed both full and shortened handshakes, negotiated PPP, and returned five of five gateway pings on each of two corrected-build calls. Subsequent full-handshake and shortened-handshake stability calls each returned 180 of 180 pings across three minutes. These are local gateway checks; they do not establish Internet throughput or universal reliability.

Later Callcentric server tests remain inconsistent. On 2026-10-10, a Quick Connect-enabled call negotiated V.92 capabilities but used full Phase 2 and V.90 data (4800 bit/s upstream, 48000 downstream); it downloaded a verified HTTPS webpage and returned 15/15 pings. No Quick Connect request or completion was logged on that call. A separate forced-full-startup call failed during retries. Earlier five-call remote checks also completed no Quick Connect attempts. Successful full or fallback calls must not be reported as Quick Connect successes.

PCM upstream training, filter negotiation, modulation and decoding remain unimplemented. PCM upstream availability is explicitly not advertised; these Quick Connect calls use the existing V.90 data path. Modem-on-hold formats exist, but a live controller with PPP state preservation is not enabled.

## Local SIP timeout diagnosis

A reproduced approximately 32-second hangup was caused by unreachable SIP Contact routing, independently of modem receive quality. Asterisk answered with its Docker address, the ATA's final-answer ACK did not arrive, and Asterisk eventually sent BYE. Correcting the published host Contact address allowed a three-minute PPP test to complete.

For published-port Docker deployments, verify the actual 200 OK Contact and matching ACK. A Docker NAT gateway can match `local_net`, suppressing the configured external address. Restart is needed for transport changes. Verify published SIP and RTP ports after restart; retain rollback configuration. Do not remove local network exclusions blindly on other deployments.

## Verification

The latest echo-window change passed 13 digital unit tests and 46 FFI tests; four checks requiring particular saved recordings were skipped. Earlier Quick Connect waveform, shortened Phase 2 and existing V.8 regression checks also passed. Hardware repeat and long-duration testing remain necessary.

## Delayed Quick Connect replies on VoIP

`V92_QC_DELAY_COMPENSATION=1` enables an optional interoperability extension
for measured delayed replies. The default remains the two-second timeout in
ITU-T V.92 section 9.2.4.3. The extension budgets one second for ANSpcm detection,
75 ms silence, 816 PCM timing symbols, the frozen measured round trip and 350 ms
for observed receive/playout and detector latency, bounded to a 2–3 second reply
deadline. An already qualifying tone has at most 100 ms additional settling time.
Missing replies still restart ordinary startup. The 980 Hz qualification and
reflection guard remain required; this option never forces CONNECT.

QC1a now has its own raw-input V.21 receiver. Framing errors in the ordinary
cancelled CM receiver no longer reset QC1a recognition. QC2a already uses raw
CRC-protected reception. Hardware verification results are recorded separately
from waveform simulations and fallback connections.
